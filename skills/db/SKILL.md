# 데이터베이스 작업

## 조회와 저장

- 테이블과 스키마의 소유자, 기존 마이그레이션과 데이터를 읽고 쓰는 경로를 확인한다. 기존 데이터 형식과 호출자가 기대하는 조회, 정렬, 갱신 결과를 기준으로 변경 범위를 정한다.
- 외부 값은 쿼리 파라미터로 바인딩한다. 단건 미조회와 DB 실패를 구분하고 실패는 저장소의 오류 형식으로 변환한다. 목록은 필터, 정렬과 동률 기준을 확인한다. 조인으로 행이 늘어나거나 목록마다 쿼리가 반복되는지 확인한다.
- 유일성, 참조 관계처럼 여러 쓰기 경로에서 지켜야 할 조건은 실제 DB 제약을 확인한다. 조건부 갱신이나 upsert를 쓸 때는 충돌 대상, 갱신할 열, 보존할 기존 값과 변경된 행 수를 확인한다. 일괄 쓰기에서는 검증과 타임스탬프가 적용되는지도 확인한다.

## 트랜잭션과 동시 실행

- 함께 커밋하거나 롤백해야 할 DB 작업만 같은 트랜잭션에 두고, 내부 호출에 해당 트랜잭션의 DB 핸들을 전달한다. 트랜잭션 안에서 느린 외부 I/O를 기다리는 경로를 확인한다. 커밋 후 후처리 실패는 이미 저장된 결과와 구분한다. 중간 실패와 재시도 후 실제로 남는 데이터를 확인한다.
- 트랜잭션을 사용한다는 이유만으로 `FOR UPDATE`, 테이블 락, advisory lock을 추가하지 않는다. 명시적 락을 추가하거나 유지하려면 초기 상태, 경쟁 요청, 실행 순서, 최종 데이터와 그 결과가 위반하는 요구사항을 확인한다. 조회 시점의 판단과 갱신 시점에 재확인할 조건을 구분한다. 어느 쪽이 요구사항인지 불명확하면 확인한다. 허용된 동시 실행과 덮어쓰기는 그대로 허용한다.
- 제약 조건과 조건부 갱신을 먼저 검토한다. 락이 필요하면 PR에 잠금 대상, 범위와 유지 시간, 관련 쓰기 경로, 경합과 교착 가능성을 적는다.

## 스키마 변경과 검증

- 테이블을 소유한 저장소의 마이그레이션을 수정한다. 기존 행의 NULL, 중복, 이전 형식이 새 제약을 통과하는지 확인한다. 배포가 나뉘면 구버전과 신버전 코드가 공존하는 순서, 데이터 채우기, 중단 후 재개와 복구 방법을 점검한다.
- 인덱스는 실제 쿼리와 실행 계획을 기준으로 선택한다. 인덱스나 제약을 추가할 때는 테이블의 쓰기 경로, 잠금 범위와 대기 영향을 확인한다.
- 저장소가 지정한 테스트 DB에서 변경 전 데이터를 준비해 마이그레이션을 적용한다. 정상 진입점에서 조회 결과와 실제 저장, 충돌, 실패 시 롤백 중 변경이 영향을 주는 동작을 검증한다.

## indentm

- 도메인의 `repository/`에서 DB 읽기, 쓰기와 예외 변환을 처리한다. 업무 함수는 파싱, repository 호출과 도메인 오류 처리를 조합한다. 모든 repository 함수는 첫 인자로 `db: Database | DatabaseTransaction`을 받고 입력은 다음에 둔다. 단건은 `get`, 여러 건은 `list`로 이름 짓고, 조회는 `try/catch`로 예외를 변환해 `Result`를 반환한다. 조회 결과는 엔티티 단위로 반환하고 여러 엔티티의 결과는 업무 함수에서 조합한다.
- `packages/core/src/db/transaction.ts`의 `transaction`을 사용한다. 성공 `Result`는 커밋하고 실패 `Result`나 예외는 롤백한다. 예상 실패는 실패 `Result`로 반환하고 예외는 `onError`에서 변환한다.

## Neoscan

- repository 함수의 첫 인자로 Ecto Repo 모듈 `repo`를 받고 입력은 다음에 둔다. 조회 결과는 엔티티 단위로 반환하고 업무 함수에서 조합한다. `try/rescue`로 DB 예외를 명시적인 오류로 변환한다. 조회 함수의 기존 반환은 `{:ok, value} | {:error, reason}`이다. 단건 미조회와 조회 실패를 구분하고 오류를 재시도 여부로 분류하도록 전환한 경로는 [function의 Neoscan 절](../function/SKILL.md#neoscan)을 따른다.
- 전달받은 `repo`의 `transact/2`를 사용한다. 콜백의 `{:ok, value}`는 커밋하고 `{:error, reason}`이나 예외는 롤백한다. 도메인 오류 분류와 트랜잭션의 실패 반환 형식은 호출 경계에서 맞춘다.
- Neoscan이 소유한 테이블은 `priv/repo/migrations/`에서 관리한다. Spray 테이블의 운영 제약과 인덱스는 Spray의 Django 마이그레이션에서 확인하고 변경한다. Neoscan의 테스트용 Spray 스키마는 `test/support/migrations/`에 있다.

## CreatorScout

- DB 작업 구성은 순수 함수에서 처리한다. 저장에 필요한 changeset이나 `Ecto.Multi`를 만들어 반환하고, 호출 측 실행 경계에서 `Core.Repo`로 실행한다. 단일 저장에 `Ecto.Multi`나 repository 계층을 추가할 필요가 있는지 먼저 확인한다.
