# 검증과 성능 계측

## 테스트

- 사용자가 보는 텍스트, 표 데이터, 선택 상태, 포커스, URL, 화면 이동, 성공과 실패를 공개 진입점에서 검증한다. 비공개 상태, 함수 이름, 내부 호출 순서나 회수, 소스 텍스트에만 의존하면 제품 동작을 검증하지 못한다. 요청 횟수나 네트워크 중단이 요구사항 자체인 경우에는 실제 요청이나 중단 결과를 관측한다.
- 테스트에서 새 동작과 기존 동작이 구별되는 초기 상태와 입력을 고른다. 같은 입력과 상태 전이의 관측만 여러 개면 한 시나리오에서 검사한다. 실패 후 이전 데이터 보존, 재시도, 오래된 응답 무시처럼 결과가 다른 분기는 독립적으로 확인한다.
- 외부 I/O는 프로젝트가 사용하는 주입 경계나 로컬 테스트 서버로 제어한다. UI에서 요청 결과를 재현하는 테스트와, 실제 클라이언트의 요청 형식 및 성공과 실패 파싱을 검사하는 테스트를 구분한다. 의도한 실행 환경에 맞춰 DOM과 서버 테스트의 preload를 확인한다.
- 폴링, 디바운스, 재시도, 만료는 지원되는 가상 타이머로 실제 예약 경로를 진행한다. React 업데이트는 `act` 안에서 완료하고, 필요한 경우 경계 직전과 직후를 검증한다. 테스트가 실패해도 정리 단계에서 가상 타이머를 복구한다. 제품 대기 시간, 데이터량, 검증 강도를 테스트 편의로 줄이지 않는다.
- E2E는 의미가 안정적인 `getByRole`, `getByLabel`, 사용자에게 보이는 텍스트를 우선하고 프로젝트 규칙을 적용한다. 공유 인증과 시드 fixture가 있으면 재사용한다. 페이지 객체는 재사용할 조작을 담고 검증 의도는 시나리오에서 읽히게 한다.

## 브라우저와 계측

- 수동 브라우저 조작에는 글로벌 지침에 따라 Chrome을 사용한다. macOS 컴퓨터 유즈는 `cua.getApp("com.google.Chrome")`으로 연결한다. Cloud에서는 관리되는 Chrome과 프로젝트가 정한 시작 명령, 미리보기 경로를 따른다. 실제 보이는 상태와 반복 가능한 assertion 중 필요한 근거를 선택한다.
- 변경 전 문제를 재현하고 변경 후 같은 환경, 데이터, 시작 상태, 클릭 순서에서 비교한다. 클릭 → 선택 표시 → 요청 시작과 종료 → 새 데이터 표시를 따로 잰다. URL만 바뀌거나 이전 데이터와 skeleton이 보이는 경우를 완료로 세지 않는다.
- 네트워크 타임라인에서 페이지 탐색과 API 요청을 확인하고 CPU 프로파일에서 React 렌더 또는 브라우저 메인 스레드 비용을 확인한다. 지연이 앞에 있으면 탐색과 클릭 처리를, 요청 중이면 서버 작업과 왕복을, 요청 뒤면 렌더링을 조사한다. 증거가 없거나 모순되면 알 수 있는 범위와 필요한 계측을 명시한다.
- 전환할 때 URL, 선택 표시, 새 목록이 같은 상태를 가리키는지 확인한다. 해당 기능의 정상 링크 진입, 뒤로 가기, 앞으로 가기, 새로고침, 빠른 연속 전환과 다른 경로 진입을 조건에 맞춰 검증한다.
- 로컬과 운영, 브라우저가 본 응답 시간과 서버 처리 시간, 측정 횟수와 중앙값 또는 분위수를 명확히 표시한다. 계측을 추가하거나 보고할 때에는 관측 항목으로 무엇을 판별하는지, 원인 확인에 어떤 증거가 더 필요한지 적는다. 관측 결과에 따라 대응이 갈리면 글로벌 지침에 따라 미확정 분기까지 Mermaid로 보여준다.

## 변경 마무리

- 저장소의 린트, 타입, 포맷, 빌드와 테스트 스크립트로 검증한다. 변경이 걸친 파일들을 함께 실행한다. 영향이 넓으면 공유 fixture와 변경이 적용될 실행 경로까지 본다.
- 최종 diff를 비교 대상으로 삼은 기존 구현과 대조한다. PR이 요청되면 재사용한 경로, 동작이 달라진 이유, 사용자가 따라할 수 있는 검증 절차를 기록한다. 관련 도구의 장애가 있었다면 복구 뒤 원래 실패했던 호출이나 브라우저 결과까지 다시 확인한다.
- 미사용 경로를 삭제하는 작업은 `dead-code-removal`을 읽는다. `router.push`, `href`, `redirect` 등의 경로 문자열까지 추적하고, 파일 삭제 및 남은 import를 확인한다. 대괄호가 있는 파일을 Git에 직접 지정할 때는 따옴표와 `:(literal)` pathspec을 쓴다.
