# React 및 Next.js

1. 사용자 요청과 작업 경로에 적용되는 `AGENTS.md`, 하위 지침, 프로젝트가 연결한 기술 문서를 확인한다. `package.json`, lockfile, 설정에서 React와 Next.js 버전, 라우터, 패키지 관리자, 실행 환경과 검증 스크립트를 확인한다. Next.js 규칙이나 API가 버전에 따라 다르면 설치본의 `node_modules/next/dist/docs/`와 deprecation 안내를 우선 확인하고 필요할 때 해당 버전의 공식 문서를 확인한다.
2. 수정 전에 같은 기능의 진입점에서 컴포넌트, 훅, URL과 데이터의 소유자, API 요청과 응답, 성공과 실패, 관련 테스트까지 따라간다. 재사용할 함수와 상태, 새 요구사항 때문에 달라지는 동작을 짧게 기록한다. 이전과 같은 동작은 기존 경로를 직접 쓰고, 근거가 있는 경우에만 새 상태, 요청, 래퍼나 의존성을 추가한다.
3. 공유와 복원이 필요한 UI 상태는 프로젝트가 이미 쓰는 URL 처리 경로를 따른다. 컴포넌트 구성, 서버 요청, 브라우저 렌더링 중 무엇이 달라지는지 확인한다. 브라우저에서 값으로 import하는 모듈의 의존성도 브라우저 경계에 포함하고, 비공개 값과 내부 전용 판단은 서버에 둔다.
4. UI를 손대기 전에 활성 디자인 시스템의 기존 컴포넌트, 토큰, 레이아웃, 카피를 확인한다. 성능 개선은 실제 병목을 계측한 뒤 적용하고, 같은 조건에서 전후를 비교한다. 정상 진입점에서 사용자가 볼 수 있는 결과를 테스트한다. 리뷰와 PR에는 실제로 수정하고 검증한 동작과 측정 환경을 적는다.
