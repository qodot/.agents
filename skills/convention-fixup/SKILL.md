# 컨벤션 수정

1. 이미 읽은 지침을 재사용한다. 작업 환경의 전역 AGENTS.md, 저장소 루트와 대상 경로의 하위 AGENTS.md에서 코드 규칙을 확인한다. 커밋 단계에는 Git 규칙도 적용한다.
2. 지정된 범위를 확인한다. 범위를 지정하지 않았으면 현재 브랜치의 미병합 변경과 git status, git diff에서 확인한 staged, unstaged, 신규 파일을 검토한다. 외부 의존성과 생성 코드는 제외한다. 대상이 많으면 논리 단위로 나누고 결과를 알린다.
3. 변경 파일을 문맥까지 읽고 지침을 위반한 파일과 줄, 위반 내용, 근거 조항을 기록한다. 명확한 수정은 원래 동작을 보존하며 적용한다. 지침 충돌, 결과가 달라지는 해석, 광범위한 구조 변경은 사용자 판단이 필요한 지점만 확인한다.
4. 프로젝트 검사로 수정 내용을 확인한다. 실패 원인을 좁혀 범위 안에서 해결한다. 기존 문제를 해결하려면 범위가 늘어나는 경우에 그 사실을 알린다.
5. 지정 커밋을 우선하고, 없으면 git log와 git show로 변경을 도입한 커밋을 찾는다. 타깃이 여럿이면 변경을 각각 스테이징해 git commit --fixup <sha>를 실행한다. 타깃이 불명확하면 후보와 근거를 제시한다.

발견한 위반과 근거, 수정한 파일, 검증 결과, fixup 타깃과 남은 항목을 보고한다.
