# Git과 PR

브랜치, 커밋, 검증과 푸시에는 작업 저장소의 Git 규칙을 함께 적용한다.

## 진행 중인 PR 수정

- 요청한 동작을 정정하거나 누락을 보완할 때는 해당 동작을 도입한 커밋과 아직 병합되지 않은 PR을 찾아 그 PR을 갱신한다. 스택에서는 변경이 속한 PR부터 확인한다.
- 기존 승인이나 커밋 수 상한을 이유로 후속 PR을 만들지 않는다. 상한에 도달하면 해당 커밋에 fixup하고 저장소 규칙에 따라 이력을 정리한 뒤 같은 PR을 갱신하고 재검증한다.
- 사용자가 분리를 요청했거나, 변경을 독립적으로 적용할 수 있거나, 기존 PR이 이미 병합된 경우에 새 PR을 만든다.

## Neoscan

- 커밋과 PR 제목은 한글로 72자 미만으로 작성한다.
- 커밋 하나의 변경은 추가와 삭제를 합산해 100줄 미만으로 제한한다.
- 커밋을 추가하기 전에 기존 커밋에 fixup으로 반영하는 것이 더 적절한지 판단하고, 그 판단에 따라 진행한다.
- PR을 작성하거나 갱신하기 전에 저장소의 `.agents/skills/convention-fixup/SKILL.md`로 PR 변경분을 검사하고, 위반 수정과 검증, fixup 커밋까지 완료한다.
- PR 하나는 커밋 3개 이하로 구성한다.
- 코드 변경은 푸시하거나 PR을 작성, 갱신하기 전에 저장소 루트에서 `mix precommit && mix assets.build && mix format --check-formatted`를 실행해 통과를 확인한다. 문서만 변경했으면 링크와 `git diff --check`를 확인한다.
- PR 본문은 아래 양식을 사용하고, 각 항목은 한 문장으로 작성한다.

```markdown
## 문제 의식
- 문제 의식 1문장

## 해결책
- 해결책 1문장
```
