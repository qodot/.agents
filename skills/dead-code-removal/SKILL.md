# 데드코드 삭제

## 범위

사용자가 확정한 제거 대상과 깊이, 제외 경계를 확인한다. 대상이 애매하거나 DB 스키마, seed, 마이그레이션처럼 되돌리기 어려운 계층에 닿으면 범위를 확인한다. 브랜치와 커밋은 프로젝트 규칙을 따른다.

## 제거

1. 삭제 전에 대상 파일의 import 전체를 읽는다. 동적 import와 side-effect import, 다른 패키지의 내부 의존성도 포함한다.
2. 대상 엔트리를 제거하고 커밋한다. 의존성은 이름, import 경로, 재수출과 문자열 참조를 검색해 남은 실제 소비처가 있는지 확인한다.
3. 제외 경계 밖에서 소비처가 없어진 의존성을 별도 커밋으로 제거한다. 그 파일의 import도 같은 방식으로 따라가 새 미사용 코드가 없어질 때까지 반복한다.

## 검증

- 최종 diff에서 삭제 파일의 import를 다시 대조한다. 유지한 모듈은 남은 소비처나 제외 기준을 확인한다.
- 라우터 탐색, href, redirect와 import에 남은 경로 문자열과 빈 디렉터리를 확인한다. 대괄호가 있는 경로를 Git에 넘길 때는 따옴표와 :(literal) pathspec을 쓴다.
- 변경 패키지의 정적 검사와 프로젝트 CI를 실행한다. 실패는 로그와 영향 경로를 좁혀 이번 변경과 관련 있는지 판단한다.
