# Elixir 작성과 리뷰

작업 경로의 AGENTS.md와 설치된 Elixir, OTP, 의존성 버전을 확인한다. [구현 전 판단](../pre-code/SKILL.md), [함수 설계](../function/SKILL.md), [테스트](../test/SKILL.md)를 함께 적용한다. 안티패턴은 조사 단서다. 실제 입력, 실행 경로, 영향을 확인한 뒤 수정한다.

## 코드와 오류

- 모듈은 CamelCase, 함수와 변수는 snake_case를 쓴다. 같은 이름과 인자 수의 함수 절은 붙여 둔다. 일반 불리언 함수에는 물음표, 가드로 쓸 수 있는 판별에는 is_ 관례를 따른다.
- 같은 연산의 입력별 처리는 함수 절과 가드를 검토한다. 분기에 필요한 값만 함수 머리에서 추출한다. 필수 키는 패턴 매칭이나 fetch 계열, 선택 키는 기본값을 받는 조회를 쓴다. 빈 맵은 map_size로 판별하고 구조체를 허용할지도 확인한다. 핀 연산자와 새 변수 바인딩을 구분한다.
- 값 변환에는 파이프, 단일 값 분기에는 case, 순차 실패 처리에는 with를 검토한다. with의 패턴 불일치는 실패값을 반환하고 등호 매칭은 예외를 낸다. 오류 출처가 중요하면 발생 지점에서 변환한다. 뜻이 다른 실패를 catch-all로 덮지 않는다.
- 예상 실패에는 반환값을 쓰고, 불변 조건 위반과 초기화 실패에는 예외를 검토한다. 실패 반환과 예외 방식이 둘 다 필요할 때만 일반 함수와 느낌표 함수를 제공한다. @spec의 입력, 선택 값과 반환을 호출부에 대조하고 외부 입력은 실행 중 검사한다.
- 상호 배타적인 상태는 상태 값으로 표현한다. 호출별 설정은 인자로 받고, 공통 설정은 시작 코드에서 읽어 의존성에 전달한다. 컴파일 시점과 실행 시점의 설정을 구분한다.
- 표준 연산을 우선한다. 목록 끝에 반복 추가하는 대신 앞에 누적하고 뒤집는다. 큰 자료의 연쇄 변환에는 Stream을 검토한다. 오래 보관할 작은 binary 조각이 큰 원본을 계속 참조하는지 확인한다. tap은 원래 값, then은 콜백 결과를 반환한다.

## OTP

- 동시성, 상태 수명, 공유 자원이나 장애 격리가 필요할 때 프로세스를 사용한다. 순수 계산을 단일 GenServer에서 직렬화하기 전에 기존 풀과 캐시, 상태 소유자를 확인한다.
- 장기 프로세스는 감독 트리에 둔다. 실제 자식 간 의존성에 맞춰 시작 순서와 재시작 전략을 정한다. 동적 자식에는 DynamicSupervisor, 동적 이름에는 Registry를 검토한다. handle_continue도 같은 프로세스에서 실행된다.
- 응답이 필요하면 call을 쓴다. call 타임아웃은 exit이며 대상 작업의 취소를 뜻하지 않는다. cast는 호출자 대기를 없애도 메일박스 부하를 없애지 않는다. 필요한 데이터만 메시지와 클로저에 담는다.
- Task의 링크, 감독, 결과, 종료, 제한 시간과 동시 실행 수를 확인한다. 여러 요청은 참조별로 추적한다. Logger 메타데이터와 로케일은 필요한 값만 전달한다. 종료 콜백이 모든 강제 종료에서 실행된다고 가정하지 않는다.

## Ecto와 Phoenix

- Ecto에서는 외부 입력의 cast와 내부 값 변경을 구분한다. 작업별 허용 필드와 필드 간 검증을 확인한다. preload의 전역 limit를 부모별 제한으로 간주하지 않는다. 쿼리, DB 제약과 트랜잭션에는 [db](../db/SKILL.md)를 적용한다.
- Phoenix 컨트롤러는 입력 파싱, 도메인 호출과 HTTP 응답을 담당한다. 인증은 실제 라우트와 Plug 파이프라인에서 확인한다. LiveView는 이벤트 입력과 권한, 재연결을 검증하고 큰 목록에는 streams를 검토한다.

## 매크로와 외부 입력

- 함수로 충분하면 함수를 쓴다. 매크로는 필요한 AST만 생성하고 컴파일 의존성을 숨기지 않는다. 컴파일 중 읽는 파일은 @external_resource로 추적한다. use가 가져오는 정의와 의존성을 확인한다.
- 외부 값은 허용 목록을 거쳐 atom에 매핑한다. 기존 atom이라는 사실이 허용 여부를 보장하지 않는다. 신뢰할 수 없는 코드 평가와 역직렬화를 피하고, 외부 URL의 목적지와 리다이렉트, SQL 바인딩, HTML 이스케이프를 실제 입력 경로에서 확인한다. 비밀값은 로그와 오류에 포함하지 않는다.

## 검증과 리뷰

- 처음 쓰는 명령은 설치본 도움말을 확인한다. 변경 범위의 테스트, 컴파일, 포맷과 실제 활성화된 정적 검사를 실행한다. 앱 시작이 외부 서비스, 큐 소비나 쓰기를 유발하는지 확인한다. 테스트에는 해당 프로젝트의 로컬 환경을 쓴다.
- 전체 검토는 소스, 테스트, 설정, 마이그레이션, 템플릿과 CI의 확인 범위를 기록한다. 호출자, behaviour, 동적 호출과 실제 입력을 확인하고 문제의 위치, 원인, 재현 조건과 영향을 보고한다. 실행하지 않은 검사와 확인하지 않은 범위를 표시한다.
- 지연은 쿼리, DB 연결 대기, 외부 요청, 메일박스와 실행 시간을 나눠 확인한다. 메모리는 프로세스, ETS, 메일박스, binary 참조와 수명을 추적한다. 타입 경고와 Credo, Dialyzer 결과는 설치 버전과 활성 규칙에 맞춰 해석한다.

## Neoscan

- 모듈은 `Neoscan` 또는 `NeoscanWeb` 이름 공간에 둔다. 프로토콜 구현과 `Mix.Tasks` 등 이름이 정해진 확장 지점은 예외다.
- 로그는 `inspect(__MODULE__)`, 입력, 결과 순서로 쓰고 입력과 결과는 `key=value`로 표시한다. 결과에 `event`를 두고 해당하는 `code`, `status`, `message`를 함께 적는다. 문자열은 `inspect/1`로 이스케이프한다. 실패 시 문제를 식별할 입력은 남기고 인증 키와 토큰은 제외한다.
- 오류 반환은 [function의 Neoscan 절](../function/SKILL.md#neoscan), 테스트 DB는 [test의 Neoscan 절](../test/SKILL.md#neoscan)을 따른다.
