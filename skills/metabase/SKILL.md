# Metabase

## 접속과 조작

- Spray와 Blaster 운영 DB 접근은 https://metabase.indentcorp.com 을 통해 수행한다. 직접 DB 접속이나 Metabase API 호출로 우회하지 않는다.
- Google Chrome 앱을 computer use로 조작한다. 다른 브라우저, 인앱 브라우저, browser use, Playwright, DOM 조작, 브라우저 JavaScript 실행은 사용하지 않는다.
- `mcp__cua_repl`의 첫 호출은 `await cua.getApp("com.google.Chrome")`로 Google Chrome 앱에 연결한다. 이후 도구가 제공하는 앱 조작 문서를 읽고 화면과 키보드, 마우스로 작업한다. 브라우저 탭 API로 전환하지 않는다.
- Chrome 앱에 연결할 수 없거나 computer use를 사용할 수 없으면 제약을 알린다. 다른 접근 수단으로 대체하지 않는다.
- 로그인은 Google 로그인을 사용하며 계정은 `qodot@indentcorp.com`이다. 이미 로그인되어 있으면 기존 세션을 사용하고, 로그인 화면에서는 해당 Google 계정을 선택한다. 사용자의 인증 조작이 필요한 단계는 요청하고 기다린다.
- 쿼리를 실행하기 전에 선택한 데이터베이스가 요청 대상인 Spray 또는 Blaster의 운영 DB인지 화면에서 확인한다. DB 표시 이름이나 ID를 추측하지 않는다.

## SQL 실행과 승인

- 데이터를 변경하지 않는 SELECT는 별도 승인 없이 실행한다. 조회 형태라도 변경 구문을 포함하거나 변경을 일으키는 함수 호출은 무승인 조회로 취급하지 않는다.
- INSERT, UPDATE, DELETE는 실행 직전에 qodot에게 알리고 명시적인 승인을 받은 뒤 실행한다. 일반적인 수정 요청만으로 실행 전 승인을 갈음하지 않는다.
- 승인 요청 전에 실제 실행할 SQL, 대상 DB와 테이블, 조건과 변경 값, 예상 영향 범위를 준비한다. UPDATE와 DELETE는 같은 조건의 SELECT로 대상과 건수를 확인한다. INSERT는 넣을 행을 제시한다.
- Slack을 사용할 수 있으면 `agent-slackbot` 스킬을 읽고 산나비 봇으로 qodot을 멘션해 승인 요청을 보낸다. 사용자와 채널은 현재 대화나 확인된 Slack 정보에서 찾고 추측하지 않는다. Slack을 사용할 수 없으면 현재 채팅 등 사용자에게 도달하는 수단으로 승인 요청을 알린다.
- 알림 전송, 이모지 반응, 무응답, 시간 경과는 승인이 아니다. qodot의 명시적 응답을 기다리며 승인 전에는 실행 버튼이나 실행 단축키를 누르지 않는다.
- 승인받은 SQL과 대상에 한해 실행한다. SQL이나 변경 범위가 달라지면 바뀐 내용을 제시하고 다시 승인받는다. SELECT 이외의 다른 쓰기 작업에도 무승인 조회 규칙을 적용하지 않는다.
- 실행 결과가 불분명한 변경 쿼리는 재실행하지 말고 SELECT로 반영 여부를 먼저 확인한다. 추가 변경이 필요하면 해당 SQL에 대한 승인을 받는다.

## 결과 확인

- Metabase가 표시한 결과나 오류를 직접 읽고 판단한다. 실행 버튼을 누른 사실만으로 성공을 보고하지 않는다.
- 결과가 많거나 화면만으로 검증하기 어려우면 Metabase UI에서 CSV를 다운로드하고 파일을 읽어 확인한다. 내려받은 CSV의 로컬 분석에는 파일 도구나 스크립트를 사용할 수 있다. 다운로드 자체는 computer use로 수행한다.
- 화면의 표시 행 수나 CSV 내보내기 제한을 확인하고, 일부 결과만 확인한 경우 전체 결과로 일반화하지 않는다.
- 변경 후에는 SELECT로 승인한 대상의 변경 결과를 확인한다.
- 보고에는 대상 DB, 실행한 SQL 또는 핵심 조건, 확인된 결과와 필요한 경우 CSV 경로를 포함한다. 오류나 결과 제한으로 확인할 수 없는 부분은 확인 불가라고 밝힌다.
