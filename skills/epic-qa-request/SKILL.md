# 에픽 QA 요청

에픽을 테스트할 준비를 마친 뒤 ella에게 Slack으로 QA를 요청한다. QA 요청 실행에는 ella의 피처 플래그 권한 추가와 Slack 전송이 포함된다. 스킬 자체의 작성이나 수정 요청을 실제 QA 요청으로 해석하지 않는다.

## 준비와 실행

1. 대화에서 대상 에픽을 식별하고 문서를 읽는다. 저장소 문서는 `docs/epics/`에서 찾는다. 대상이 모호하면 질문한다. 메시지에 넣을 문서 링크는 해당 에픽의 실제 Notion 페이지나 GitHub 문서 링크를 사용한다. 로컬 경로로 대신하지 않는다.
2. 에픽 문서와 구현에서 해당 기능을 제어하는 피처 플래그 키를 확인한다. 피처 플래그 없는 에픽은 이 절차의 유효한 대상이 아니다. 키를 찾을 수 없으면 누락으로 보고하고 필요한 정보를 질문한다. 플래그 없이 요청을 보내거나, 이름을 추측해 플래그를 새로 만들지 않는다.
3. [featureflag-managing](/Users/qodot/.codex/skills/featureflag-managing/SKILL.md)을 읽고 프로덕션 관리 화면에서 ella의 서비스 계정에 해당 플래그를 허용한다. 기존 공개 대상을 유지하며 ella의 개별 사용자 권한을 추가하고, 저장 후 반영을 확인한다. 이미 개별 허용되어 있으면 유지한다. Slack의 ella와 서비스 계정의 ella를 각각 확인하고, 동명이인 등으로 식별이 불명확할 때만 질문한다.
4. 해당 기능이 프로덕션에 반영되었고 테스트 화면에 접근할 수 있는지 확인한다. 메시지에는 실제 테스트를 시작할 수 있는 프로덕션 링크를 넣는다. 특정 캠페인이나 데이터가 필요하면 그 화면의 링크와 최소한의 준비 조건을 적는다. 로컬, 프리뷰, PR 링크로 대체하지 않는다. 배포나 테스트 데이터 준비가 막혀 있으면 필요한 후속 조치를 보고하고 요청 전송을 보류한다. QA 요청을 위해 임의로 배포하지 않는다.
5. 문서의 핵심 요구사항과 실제 화면을 기준으로 테스트 방법을 아주 쉽고 짧게 요약한다. 클릭할 곳과 확인할 결과를 짝지어 적고, 구현 용어와 긴 체크리스트를 넣지 않는다. 가능하면 2~4단계로 끝내되 핵심 동작은 빠뜨리지 않는다. 이 스킬이 사용자를 대신해 프로덕션에서 발송이나 삭제 같은 업무를 실행할 필요는 없다.
6. [agent-slackbot](/Users/qodot/.agents/skills/agent-slackbot/SKILL.md)을 읽고 산나비 봇으로 `#indentm` 채널에 아래 내용을 한 메시지로 보낸다. 채널과 ella의 Slack 사용자를 조회해 확인하고, 표시 이름 텍스트가 아닌 `<@사용자ID>`로 멘션한다. 사용자가 QA 요청을 지시했다면 초안 승인 절차를 추가하지 않고 준비를 마친 후 전송한다.

## 요청 메시지

아래 형식의 자리표시자를 확인한 값으로 바꾼다. 테스트 단계 수는 실제 기능에 맞춘다.

```text
<@ella의 Slack 사용자ID> <에픽 제목> QA 부탁드려요!

에픽: <에픽 문서 링크>
피처 플래그: <플래그 키>, ella 계정 허용 완료
테스트: <프로덕션 링크>

테스트 방법
1. <화면에서 할 행동>
2. <다음 행동> → <보이면 되는 결과>
```

전송 성공 여부를 확인하고 사용자에게 보낸 메시지의 Slack 링크를 보고한다. 전송 결과가 불명확하면 채널에서 기존 메시지를 확인한 뒤 재시도해 중복 요청을 피한다. 권한 추가 후 전송에 실패했다면 권한 반영 상태와 전송 실패를 구분해 보고한다.
