# API 작성과 리뷰

## HTTP 경계

- 같은 기능의 호출자, 라우트 등록과 미들웨어, 핸들러, 도메인 함수, 요청 테스트를 따라간다. 메서드, 경로, 입력 기본값, 상태 코드와 응답 형식은 호출자가 의존하는 동작과 대조한다. 변경이 필요하면 영향받는 호출자와 호환 방법을 확인한다.
- 라우트를 추가하거나 바꾸기 전에 기존 라우트와 호출자, 관련 테스트에서 경로와 파라미터 이름의 언어, 구분자, 기본값과 적용 범위를 확인한다. 새 엔드포인트나 콜백은 기존 경로로 충족할 수 없는 요구사항을 확인한 뒤 추가한다. 수정 후 등록한 경로와 호출 URL을 대조한다.
- 경로 변수, 쿼리, 본문과 헤더를 HTTP 경계에서 파싱한다. 기존 도메인 스키마나 파서를 재사용하고 HTTP에서 필요한 필드와 변환만 추가한다. 핸들러에서 파싱한 값을 도메인 함수에 전달한다.
- 기존 오류 종류를 상태 코드와 공개 오류 형식에 빠짐없이 대응시킨다. 성공 응답은 필요한 필드만 선택해 직렬화한다. 날짜를 ISO 문자열로 바꾸는 등 전송 형식 변환은 핸들러에서 담당한다. 내부 오류 상세, 비밀값, 호출자에게 공개할 수 없는 필드는 응답에 담지 않는다.

## 인증과 리소스 권한

- 실제 라우트에 연결된 인증과 권한 미들웨어를 확인한다. 실행자, 리소스 소유자, 요청이 지정한 상위 리소스를 구분한다. 상위 리소스의 접근 권한과 하위 리소스의 소속, 작업별 상태 조건을 각각 확인한다.
- 권한 경계에서 보장한 검사는 재사용한다. API에서 허용한 요청이 도메인 조회나 쓰기 조건에서 다시 차단되거나, 반대로 라우트를 거치지 않는 호출 경로에서 검사가 빠지지 않는지 확인한다. 웹훅에는 제공자 인증과 기존 중복 처리 규칙을 적용한다.

## HTTP 클라이언트와 검증

- indentm과 Neoscan의 내부 웹 요청 함수는 핸들러와 같은 도메인 경로와 액션 이름으로 두고 동적 ID 디렉터리를 제외한다. 요청 함수는 액션별 한 파일에 두고, 기존 네트워크 클라이언트를 첫 인자, 요청 입력을 다음 인자로 받아 직접 호출한다. 요청과 응답 타입, 응답 파서는 같은 파일에 둔다.
- 외부 연동은 서비스별 클라이언트에서 인증, URL, HTTP 요청과 응답 처리를 재사용한다. 같은 연동이 업무 모듈에 이미 있다면 클라이언트로 옮겨 기존 호출자와 공유한다.
- 응답 상태와 본문을 파싱해 호출자가 다르게 처리할 HTTP 오류, 네트워크 실패, 응답 형식 오류를 구분한다. 쓰기 요청에서 응답만 유실될 수 있다면 재시도 전에 원격 반영 여부와 중복 실행 방식을 확인한다.
- 실제 라우트에서 요청, 권한, 상태 코드, 응답 본문과 저장 등 관찰 가능한 결과를 검증한다. 클라이언트의 요청 형식과 응답 파싱은 로컬 HTTP 서버 등 실제 HTTP 경계에서 검증하고, 업무 테스트에는 주입한 클라이언트 메서드의 반환값을 사용한다. 전역 HTTP 함수를 덮어쓰거나 테스트만을 위한 전송 함수를 추가하지 않는다.

## indentm

- 크론과 일반 핸들러는 `apps/api/src/routes/`에 액션당 한 파일로 두고 디렉터리의 `index.ts`에서 등록한다. 도메인 함수는 대응 패키지에 같은 도메인 경로와 액션 파일명으로 두고 `index.ts`에서 공개한다. 핸들러와 도메인 함수의 파일 경로에는 동적 ID 디렉터리를 만들지 않는다.
- 웹 요청 함수는 `apps/web/src/lib/`의 대응 경로에 둔다. 응답 스키마에서 타입을 추론하고 파싱 결과는 기존 `Result`로 반환한다. API 핸들러는 도메인 오류를 `match().exhaustive()`로 상태 코드에 대응시킨다.
- 외부 서비스 클라이언트는 클래스나 객체를 반환하는 팩토리로 만든다. 생성 시 받은 인증과 연결 설정을 클라이언트가 보관하고 공통 HTTP 요청과 API 액션은 메서드로 구현한다. 업무 함수는 필요한 기존 클라이언트 타입을 개별 인자로 받아 메서드를 직접 호출한다. 변경 대상 연동에 적용한다.
- API와 코어의 캠페인, 세션 및 하위 리소스 작업은 `hasPermissionOfCampaign`, `hasPermissionOfAgentSession`과 `apps/api/src/middleware/`의 `has-campaign-permission.ts`, `has-agent-session-permission.ts`를 재사용한다. 소유자와 `roles`에 `admin`이 있는 사용자는 조회와 변경이 가능하다. 캠페인과 세션의 루트 목록은 admin에게도 본인 소유만 반환한다. 하위 리소스의 소속과 보관, 삭제, 활성 상태 등 작업 조건은 admin에게도 적용한다. admin의 실행자 ID를 소유자 ID로 바꾸지 않는다.
- 권한을 바꿀 때는 소유자와 타인 리소스에 접근하는 admin의 허용, 소유자도 admin도 아닌 사용자 거절, 상위 리소스 불일치, 루트 목록의 소유 범위 중 해당하는 동작을 검증한다. 선례는 `apps/api/src/routes/`의 `campaigns/list.test.ts`, `agent-sessions/list.test.ts`, `campaigns/agent-sessions/agent-messages/list.test.ts`, `campaigns/proposals/share-links/share-links.test.ts`를 본다.

## Neoscan

- API와 크론 라우트는 `lib/neoscan_web/router.ex`에서 등록한다. 핸들러는 `lib/neoscan_web/controllers/`, 도메인 함수는 `lib/neoscan/`에 대응하는 도메인과 액션 이름으로 배치하고 동적 ID 디렉터리를 제외한다. 액션별로 파일을 두고 공개 도메인 함수는 `def`로 선언한다.
- 서비스 API는 실제 라우트가 인증 Plug를 통과하는지 확인한다. 도메인 오류는 컨트롤러에서 패턴 매칭으로 상태 코드와 본문에 대응시킨다.
- 내부 웹 요청 함수는 응답 파서의 반환 타입을 명시하고 기존 `{:ok, value} | {:error, reason}`을 반환한다.
